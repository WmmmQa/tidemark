# Tidemark — 本量利、产品组合与预算执行分析库

## 需求与生态定位

小微经营者、财务管理学习者和经营分析工具开发者，需要把定价、产品结构与分期预算转换成可复核的数量计划和利润解释。Tidemark 提供 MoonBit 原生计算组件：单产品本量利、多产品销售组合、多期间经营计划和预算实际差异分析。与通用货币、现值、贷款日程等方向相比，重点是经营贡献、销售结构、分期利润及差异对账；不扩展为会计核算或税务软件。生态相邻项目可参见 [Aurum](https://github.com/Lyllyl789/aurum) 与 [moonmoney](https://github.com/haol-05/moonmoney)，本项目不移植其实现。

### 与相邻项目的边界

截至 2026-10-23 核对的 Mooncakes 发布版中，[moonbit-accounting 0.3.0](https://mooncakes.io/docs/mhlagent/moonbit-accounting@0.3.0) 从会计分录生成报表，也提供报表行金额的预算差异及分期报表；[finapp 0.1.2](https://mooncakes.io/docs/bobzhang/finapp@0.1.2/shared) 管理个人账户、交易和分类消费限额。Tidemark 的输入是产品售价、单位变动成本、销量与共享固定费用，交付销售配比规范化、整组合目标数量及按数量、售价、单位变动成本、固定费用严格对账的利润桥。这与报表金额比较、个人消费进度存在概念交集，但计算模型和接口用途不同。

上述比较限定于已核对的版本，不声称 MoonBit 生态没有其他财务或预算工具。Tidemark 可作为经营分析工具的独立计算组件，目前未声明与上述项目已有集成；外部工程的源码接入步骤见[库接入说明](using-as-a-library.md)。

接入验证会在独立 MoonBit workspace 中以 sibling module 导入全部五个公开包，并实际调用计算与 JSON API；GitHub Actions 在 JS 与 Linux native 后端运行该消费者示例。

## 三个完整使用场景

1. **餐饮组合与目标利润：**餐品售价/单位变动成本 ¥80/¥48，饮品 ¥50/¥30，销售配比 2:1，共享固定成本 ¥16,000。运行 `examples/product-mix.json`，得到组合贡献 ¥84、保本 191 个组合（382/191 件）；目标利润 ¥8,000 需要 286 个组合，收入 ¥60,060、利润 ¥8,024。应用可显示整组合取整产生的 ¥24 富余。
2. **连续月份经营计划：**运行 `examples/operating-plan.json`，十月按 2:1 数量结构测算利润 ¥5,000；十一月改成 1:2，饮品单位成本增加、固定费用提高，得到亏损 ¥1,000。分期结果及累计指标显示两月利润 ¥4,000，距离两月合计 ¥12,000 的利润目标还差 ¥8,000。结果不将不同销售组合的保本件数简单相加。
3. **预算执行复盘：**运行 `examples/budget-actual.json`，按期间和产品 ID 对齐预算与实际，允许输入行顺序不同。两期预算利润 ¥14,200、实际 ¥4,660，差额 −¥9,540；按产品数量、售价、单位变动成本和固定费用分解为 −¥1,160、−¥3,040、−¥2,840 和 −¥2,500，四项严格对账。调用者可以逐产品、逐月份解释差异。

上述为不同的假设案例。运行方式统一为 `node scripts/analyze.mjs examples/文件名.json`，复制 JSON 后可修改输入；文件、字段、单位、结果和错误均有公开说明。

## 可复用实现与边界

- `domain` / `engine`：保留单产品贡献、贡献率、保本、目标利润销量/收入、利润、安全边际、情景与敏感性分析。
- `portfolio`：产品身份、整数配比规范化、共享固定费用、完整组合保本/目标计划、产品明细与方案比较。允许亏损单品，要求组合整体贡献为正。
- `planning`：独立的单期/多期计算 API、累计收入成本利润与有符号目标缺口、预算实际对齐和四因素利润差异分解。允许零销量、零售价及亏损；产品可跨期变化，比较双方的同期间产品集合须一致，缺失数据不静默补值。
- `interchange` / `cmd/report`：复用标准 JSON 解析器，提供版本化请求及机器可读结果。Node 包装器只负责读取文件、调用 MoonBit 和退出状态；财务计算、字段解析与结果构造由 MoonBit 完成。

金额使用整数分，销量使用产品各自的整数单位。单项输入金额、目标和期间单品数量上限为 10 亿，派生结果与每一步累计/差额运算必须能由 `Int64` 表示。类型化错误携带字段、产品/期间或运算上下文，不输出溢出后的结果。JSON 金额和数量以十进制字符串传输，避免 JavaScript 精度损失；命令传输上限 16,000 个 UTF-16 单元，纯计算 API 不受此文本限制。

模型假设币种、成本口径和产品计量单位一致；各期间价格、成本和销量由调用方明确提供。固定费用每期只扣除一次。差异分解采用数量→售价→单位变动成本→固定费用的替代顺序，数量效应包含产品结构变化，结果是会计分解而非因果证明。经营利润不等于现金流；不涵盖需求预测、产能优化、库存、税务和准则判断。

## 工程交付

原创实现，Apache-2.0 许可证，公开 Git 历史保留实质开发记录。测试覆盖比例等价、目标取整最小性、亏损与零销量、期间累计、ID 对齐与缺配对、不同变化驱动、利润桥恒等式、整数溢出及 JSON/CLI 错误；固定演示之外还有参数网格与边界验证。GitHub Actions 执行格式、生成接口、原生编译、原生/JS 测试和可编辑文件流程。API 及调用方式见 README 和生成接口，输入约定见 `fieldbook/json-interface.md` 与 `schema/request.schema.json`。Mooncakes 发布另按发布清单准备。
